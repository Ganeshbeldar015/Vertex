# T-0003 — Multi-Hop Reasoning & Action Layer

Backlog ref: BL-004, BL-005, BL-006 · Sprint: 3 · Priority: MUST

## Intent
Implement autonomous multi-hop reasoning with explicit hypothesis testing, a composite risk scoring tool (`score_risk`), and a simulated core banking action service with risk-tiered approvals and immutable audit logging. This enables the agent to evaluate multiple fraud scenarios, synthesize evidence into a numerical risk score with feature contributions, and recommend or queue remedial actions (freeze accounts, block devices) safely.

## Scope / Out of scope
- **In Scope:**
  - `score_risk` tool combining graph features (shared devices, circular flows, community density, velocity) with factor attribution.
  - Multi-hop agent hypothesis evaluation (testing shared device collusion vs. mule routing).
  - Simulated core banking action service (`src/actions/service.py`) supporting `flag_entity`, `create_case`, `freeze_account`, `block_device`, `notify_analyst`.
  - Risk-tiered approval matrix: low risk auto-executed, medium risk requires 1-click approval, high risk requires explicit review.
  - Action reversibility (unfreeze, unflag) and immutable `ActionLog` audit trail.
  - Integration with `SengraMCPServer` exposing `action.*` and `algo.score_risk`.
- **Out of Scope:**
  - Frontend graphical canvas and live web dashboard (Sprint 4).
  - Real-world production core banking integrations (simulated service is the approved design).

## Guidance
- Actions must be idempotent: executing the same action twice with the same idempotency key must not produce duplicate entries or state corruption.
- Write tools (`action.*`) must require a case ID and evidence list before execution.
- Gated actions (`freeze_account`, `block_device`) must enter `PENDING_APPROVAL` status and never execute without an explicit approver.

## Requirements
- REQ-007: Composite risk scoring tool (`score_risk`) with explainable factor breakdown.
- REQ-008: Implement autonomous agent reasoning loop.
- REQ-009: Enforce step budget (max 15 tool calls), token budget, loop breaker.
- REQ-010: Write-back and simulated action tools (`flag_entity`, `create_case`, `freeze_account`, `block_device`).
- REQ-011: Risk-tiered approval matrix.
- REQ-012: Action guardrails: reversible actions, idempotency, immutable `ActionLog`.

## Acceptance
- **AC-003-a (Risk Scoring):** Given target account `A-1042`, When `score_risk` runs, Then it returns a composite risk score (0.0 to 1.0) and ranked factor contributions (shared devices, circular flow, community density).
- **AC-003-b (Hypothesis Testing Loop):** Given an alert on `A-1042`, When the agent investigates, Then it formulates hypotheses, executes multi-hop checks (shared attributes, community detection, cycle detection), and determines fraud ring involvement within 15 tool calls.
- **AC-003-c (Gated Actions & Approval Queuing):** Given an investigation finding high-risk accounts (`A-1042`, `A-1050`), When the agent requests account freezes, Then actions are queued in `PENDING_APPROVAL` status with evidence IDs attached.
- **AC-003-d (Action Execution & Reversal):** Given a queued freeze action, When an authorized approver approves it, Then status transitions to `COMPLETED`; When unfreeze is requested, Then account status returns to active.
- **AC-003-e (ActionLog Audit Trail):** Given any executed or queued action, When inspecting the action log, Then an immutable record with action ID, type, target, approver, evidence references, and timestamp exists.

## Risks / Notes
- Unapproved execution risk: Ensure gated actions cannot be triggered autonomously by the agent without approver intervention.
